## Thread 1 — governance applicability

### Binding constraints

- ✓ **POL-001** (no parallel implementation). Reuse `credential.Token` /
  `bearer`, the `Send` seam, `error`, `render.envelope` and the test support
  helpers. Do not add a second HTTP client or credential reader.
- ✓ **DEC-006** (pure core, one injected HTTP seam).
  - The seam is `Send = fn(Request(String), Int) -> Result(Response(String), HttpFailure)`
    (`src/screwtape/jmap/client.gleam:43-44`).
  - The classify codec and the PII pass are pure modules.
  - Classify injects `Send` and never imports `httpc`.
- ✓ **DEC-012** (key ingress).
  - The key is read from `$CREDENTIALS_DIRECTORY/<name>` and wrapped in an
    opaque closure `Token`.
  - Only the header builder reveals it.
  - Sentinel tests assert that it is absent from stdout, stderr and errors.
  - argv carries only the credential name.
- ✓ **DEC-016** (runtime account). Screwtape runs as a Home Manager
  `systemd --user` unit under the operator's uid. Its credentials are
  user-scoped (`systemd-creds encrypt --user`). This supersedes DEC-002/003.
- **DEC-001** (credential custody). A key is provisioned once and encrypted,
  then loaded with `LoadCredentialEncrypted=`. It is never resolved at run
  time.
- **DEC-018** (TLS). Configured URLs must be https. `ca_file` is optional and
  peer verification stays on.
- **DEC-014** (one error type). Errors carry type strings, never response
  bodies. Jev output is attacker-influenced, so a decode failure carries a
  path, not a payload.
- **DEC-011** (CLI shape). argv is matched by hand; output uses the envelope
  `{version, kind, data}`. Exit codes: 0 for success, 2 for usage or config
  errors, 1 for anything else.
- ✓ **DEC-029** (versioning). There is one contract version, now 1.
  - New verbs and new fields keep the version.
  - **Adding a value to an existing enum bumps it.**
- **DEC-030** (publishing). The contract is documented in README field tables
  and pinned by render and CLI tests. There is no JSON Schema.
- **DEC-027 / DEC-028 / DEC-032** (the published pipe surface). Classify
  consumes only that surface. ✓ `read --after` emits one `read` envelope per
  line, oldest first (`README.md:240-245`, `src/screwtape/cli.gleam:258-265`).
- **DEC-008** (sync wipes the data tables). Classifications must not be
  stored.
- ✓ **DEC-009** (config and request policy).
  - There is one JSON config, generated by the module.
  - **Concurrency 1; no retry, including httpc's autoretry.**
  - "The next timer tick is the retry". That rationale is sync-specific.
- **SPEC-002 NF-006** (no host literals). The Jev or gateway base URL comes
  from config.

### Tensions / revision candidates

1. ✓ **DEC-012 assumes systemd.** The verb fails with
   `Credential("no_credentials_directory")` when `CREDENTIALS_DIRECTORY` is
   unset (`src/screwtape/cli.gleam:346-352`). Classify runs in a shell
   pipeline, so it has no credentials directory unless something provides
   one (see Cross-thread finding A).
2. **README contract scope.** The README defines the contract as "what the
   read verbs print". A `classify` envelope is a new `kind`, which DEC-029
   permits within version 1. But the classification *enums* (tags, choice
   names) then freeze under DEC-029.
3. **satan:RFC-020 D1** says "Milestones 1 and 2 involve no LLM". Jev is a
   decision model, not an LLM. Record that framing durably, or amend D1 to
   "no model inference in the mirror". classify runs outside `sync`, so the
   mirror itself stays model-free.
4. **satan:RFC-020 D5:** the "pre-classified subset" amendment that IDE-001
   promised. It is not yet drafted.
5. **satan:SPEC-002 NF-004** (jails that hold model output). This applies if
   SATAN runs classify inside a jail. It is M3's concern, noted here.
6. **DEC-016's accepted exposure** (a decrypted token is readable by the
   operator's processes while a run is live) now extends to the Jev or
   gateway key and to mail text in flight. Say so explicitly.

### Cited facts

- ✓ The core is pure. `cli.run` returns `Outcome(stdout, stderr,
  exit_code)`, and the whole stdout is built as one string, then printed
  (`cli.gleam:52-56`, `:258-265`). stdin would arrive the same way: read at
  the edge and passed in.
- ✓ `gleam.toml` has no regex dependency, and the pinned stdlib has no
  `gleam/regex` (`test/check_imports.gleam:14-16`). The options are:
  - Erlang's `re` (PCRE, part of OTP) through FFI;
  - the `gleam_regexp` package;
  - a hand-written scanner.
- There is no envelope decoder in `src/`; tests decode dynamically.
  `jmap/decode.gleam:812-818` has a generic `decode.document` that reports a
  `Decode(path)` on failure.
- Two layers of HTTP fakes are available:
  - `test/support/fixture_send.gleam`: a scripted in-process `Send`;
  - `test/support/local_jmap.gleam` + `local_tls.gleam`: a real loopback TLS
    server.
- Redaction: `test/screwtape/token_leak_test.gleam` (one sentinel token) and
  `credential_test.gleam:115-125` (pins `Token.inspect`).
- Shared CLI fixtures: `test/support/cli_fixture.gleam`. Its helpers are
  `config_text`, `credential_dir`, `token`, `stdout_json`, `field` and `keys`.

### Naming precedents

- Modules are named `<domain>/<role>`, e.g. `jmap/client`, `jmap/decode`,
  `store/codec`.
- Functions are verb-first. Decoders end in `_decoder`, encoders in `_json`,
  accessors in `_of`.
- Error constructors are PascalCase with snake_case reason codes, which may
  name a field (`non_https:session_url`).

## Thread 3 — Jev API

### Request — `POST /v1/systemone`

- Body (`SystemOneRequest`):
  - required: `model`, `state`, `questions`;
  - optional: `assets`.
- `state` may be a string, an object or an array.
- `questions` maps a name you choose to a question, and needs at least one
  entry.
- Auth: `HTTPBearer`.
- The body may be JSON or multipart. Multipart is only for assets.
- Question types:
  - **choice**: `criteria` maps each name to a description of when it
    applies. The answer is `{choice, confidence, probabilities}`, a single
    choice.
  - **score**: `criteria` is an ordered list of 1–10 level descriptions. The
    answer is `{score, confidence, legend, probabilities}`. `score` is a
    probability-weighted average, so it can fall between levels.
  - **noul**: an optional `{true, false}` description. The answer is
    `{noul}`, a number from 0 to 1, with no confidence.
- Each question can also carry `instructions` (a string, object or array).
- Response (`SystemOneResponse`): `{model, answers, usage}`.
  - `answers` is keyed by question name.
  - `model` is the versioned id that answered.
  - `usage` is `{input_tokens, output_tokens}`.
- Questions in one request are evaluated in parallel against the same
  `state`.

### Limits and errors (docs: `api/errors`, `models`)

- Body: at most 32 MiB; a larger body returns 413.
- Nesting: at most 64 levels.
- Context: 64k tokens for the whole request, and 32k tokens for `state` plus
  any one question. There is no cap on the number of questions. A request
  that is too long returns 400 `max_tokens_exceeded`.
- Status codes: 400, 401, 413, 415, 422 (validation), 429 (rate limit) and
  529 (overloaded). The docs advise exponential backoff. No numeric rate
  limit is published.
- The SDK defaults to retrying 408, 429 and 5xx with a 10 s per-attempt
  timeout (`src/types.ts:260-320`).
- Compression is out of scope (operator, 2026-10-28).

### Models and cost

- `jev-1.14.0` and `jev-1.13.0` are available. `jev-latest` points to 1.14.0.
- The docs recommend pinning a versioned id when confidence thresholds are
  tuned against it, because an alias can move.
- Price: $0.042 per million input tokens; output is free.
  - 1,000 mails at about 2k tokens each is about $0.0001.
  - Cost is not a design driver.

### Confidence

- Choice and score answers carry a confidence of 1 − spread.
- The docs give no universal thresholds. Their examples route anything under
  0.5 to a human and act only above 0.9. For noul they suggest about 0.7 for
  yes and 0.3 for no.
- Recommendation: emit the raw numbers and leave thresholds to consumers.

## Cross-thread findings

**A. Key ingress for a shell verb.**

This is the highest-value finding. Combine DEC-012 (the key is read from
`$CREDENTIALS_DIRECTORY`), DEC-001 (no run-time resolution) and a verb run in
a shell pipeline (no systemd). Three options:

1. **`systemd-run --user --pipe -p LoadCredentialEncrypted=jev:<path> screwtape … classify`.**
   This is the same custody as DEC-001/016 and changes no Screwtape code.
   The module or a wrapper script bakes it in.
2. Point `CREDENTIALS_DIRECTORY` at a directory holding a plaintext 0600 key
   file. This weakens DEC-001.
3. A new ingress path, which would need a DEC.

Option 1 is the simplest. ✓ A spike on 2026-10-28 confirmed it:

- `printf … | systemd-run --user --pipe --quiet --wait -p LoadCredential=jev:<file> sh -c 'cat; …'`
  streamed stdin to stdout;
- it set `CREDENTIALS_DIRECTORY=/run/user/1000/credentials/run-….service`
  with the key inside;
- it propagated the exit code (3 → 3).

The spike used `LoadCredential=` with a plaintext dummy key.
`LoadCredentialEncrypted=` uses the same path, as in DEC-016's unit.

**B. The interim direct key and the gateway share one shape.**

- Both use the same `POST /v1/systemone` body with `model` in it and an
  `Authorization: Bearer` header.
  - Upstream: verified in the OpenAPI spec.
  - Gateway: per flakes:IMP-054's reading of LiteLLM 1.106.2. Not checked
    here.
- Swapping between them is config only:
  - `base_url`: upstream `https://api.typesafe.ai`, or the gateway relay;
  - the credential name: the TypeSafe key, or a gateway client key;
  - the model id: the gateway may name it `typesafe/jev-1.14.0`.
- **Caveat:** the gateway relay is plain `http://127.0.0.1:<port>`, or a unix
  socket. DEC-018 requires https for configured URLs. So the swap needs one
  of these:
  - a loopback-http exception;
  - a unix-socket transport;
  - TLS on the relay.
  Decide in design or at swap time.

**C. The seam is generic but lives in the wrong module.**

- `Send` and `HttpFailure` are not JMAP-specific, yet they live in
  `jmap/client`.
- POL-001 says generalise rather than copy. So move them to a neutral module
  (e.g. `screwtape/http`) and give it a small shared status mapping. Both
  `jmap/client` and the Jev client would use it.
- This is a refactor-first step that design should name.

**D. Retry policy diverges.**

- DEC-009 says "no retry", because the next sync tick is the retry.
- Classify has no tick, and Jev documents 429 and 529 as retryable.
- Simplest option: no retry. Fail closed for that message, emit a per-message
  error line and let the consumer re-run. The `--after` cursor makes re-runs
  cheap.
- Retrying would need a decision that DEC-009 does not cover.

**E. Fail-closed unit and output framing.**

- One request per message gives per-message failure isolation and matches
  `read --after`'s one-line-per-message output.
- Jev's per-question cap (32k tokens) and `max_bytes` from `read --after`
  already bound `state`.
- Batching several messages into one request is not possible: there is one
  `state` per request.
- So the design is one request per message, with every question in that
  request.

**F. Enum freeze (DEC-029) versus an evolving taxonomy.**

- The mail-type tags and risk names would be choice names or question names
  in the output.
- If they are contract enums, every new tag bumps the version.
- Two ways out:
  - version the question schema separately: a `schema` field in the
    classification envelope, with consumers matching on it;
  - declare the question names open-ended (a map, not an enum).
- Design choice.

## Design-input deltas

1. Screwtape holds a Jev key now and a gateway client key later. The config
   gains `base_url`, `credential_name` and `model` for Jev. IDE-001's "own
   key" survives only for the interim.
2. Add a refactor phase first: lift `Send`, `HttpFailure` and the status
   mapping out of `jmap/client` (C).
3. stdin enters at the process edge as a string, so `cli.run` stays pure.
4. Use one request per message, holding all the dimension questions. A
   failed message emits an error line; there is no retry (D, E).
5. The mail-type tags cannot all be one `choice` question, because a choice
   question has a single answer. Use one `noul` per tag; risks are also
   nouls. Interest and urgency are `score` questions.
6. PII stripping needs a regex engine. Prefer Erlang `re` through the
   existing FFI module, since it adds no dependency. Decide in design.
7. Key ingress: `systemd-run --user --pipe -p LoadCredentialEncrypted=…`,
   which the spike proved (✓ A). It needs no code change to `credential`.
   The module or a wrapper bakes in the invocation.
8. Gateway swap caveat: https-only config versus the plain-http relay (B).
9. Output: emit raw probabilities and confidences plus the answering `model`
   id. Thresholds belong to consumers.
