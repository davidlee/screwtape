## Thread 1 — governance applicability

### Binding constraints

- **DEC-034** (accepted) fixes the state: `{subject, sender_domains, sender_domains_omitted, bodies[], bodies_omitted, attachments[], attachments_omitted}`, "No display names, local parts, other address fields", and "Texts are stripped first and cut to their bounds after, since stripping can lengthen text". SL-005 reverses the cut order (`slice-005.md:37` "Reverses DEC-034's") and adds fields, so DEC-034 must be superseded or amended by name — the change is not a free re-implementation. Current code obeys the old order: `state.gleam:67-68` (`pii.strip` → `utf8.prefix`), `state.gleam:119` then 120 (`let sent = utf8.prefix(stripped, remaining)`).
- **DEC-035** (accepted): "Any change to questions, instructions, criteria, rubrics or **state preprocessing** bumps the schema id." Goals 1, 2 and 5 all change preprocessing, so `mail-1` (`schema.gleam:11`) cannot be reused; SL-005 objective 6 says the same (`slice-005.md:51`). A schema bump is not a contract-version bump — that separation is DEC-036's point.
- **DEC-036** (accepted): the classify line is `{version: 1, kind: classify, data: {id, cursor, schema, model, answers}}`, vocabulary owned by `schema` not by contract enums. `seen` (goal 3) is therefore a new key inside `data`, and `README.md:220-233` must gain a row rather than reorder existing ones.
- **DEC-029** (accepted): "Within a version: new fields, new verbs, new optional flags"; a bump is needed for "removing, renaming or retyping a field; changing a field's meaning or an ordering". This is the sharpest constraint on SL-005 and it is in tension with the slice: adding six address lists plus `seen` is additive, but *replacing* `state.sender_domains` is a removal of a documented field.
- **README `## Contract` compatibility paragraph**, `README.md:119-125`: same rule as DEC-029 in consumer-facing words — additions keep version 1, "raising the version is reserved for removing, renaming or retyping a field … and for adding a value to an existing enumerated field (`source_type`, `truncated_by`)"; "consumers must ignore fields they do not know" (`README.md:121`). Because `README.md:246-257` documents each `state.*` field individually, those fields *are* contract surface, not internals.
- **DEC-030** (accepted): the contract is "documented in the README and pinned by render and CLI tests", consumers "write their own types from the README tables". Practically: `test/screwtape/classify_state_test.gleam:38-39` decodes `sender_domains`/`sender_domains_omitted`, and `test/screwtape/docs_test.gleam:31-35` parses `README.md`'s `### mail-1` table and fails on drift. Goal 4 (README raw bounds) must land in the same change as the code, and the new bounds tables should be pinned the same way the `mail-1` table is.
- **POL-001** (required): "Every behaviour has one implementation … Extend or adapt it rather than writing a second version beside it." This decides the flag question in the operator's favour only in one form: a parameter threaded through `pii.strip` (`pii.gleam:203-222`) is one implementation; a relaxed stripper beside `pii.strip`, or a second state builder, is the prohibited parallel path. Note also `pii.gleam`'s rules are `re` patterns executed through `src/screwtape_pii_ffi.erl`, which `check_imports_test.gleam:56,212-243` allowlists by name — a rewrite that adds FFI surface must keep that guard coherent.
- **POL-002** (required): "Real, unscrubbed mail content lives only outside the repository … including its PII-stripped `classify --state` form" and "Never quoted out … not into … doctrine records … code comments, test fixtures". The relaxed rules (goal 5) need keep/erase cases and README examples drawn from hand-made or provenance-recorded scrubbed fixtures in `test/`, never from `~/.local/state/screwtape/eval/`.
- **DEC-039** (accepted) plus `slice-005.md:54-55` ("`jev_context` and its cursor-bearing error line are unchanged"): raw-before-strip lets stripped text grow, so `max_tokens_exceeded` is *more* reachable, not less. The 400-recognition path (`detail.error_type` or the LiteLLM-wrapped string) must survive untouched, and SL-005's "verify Jev token limits" item is an obligation here, not a nice-to-have (`slice-005.md:80-83`).
- **SL-004's locked design** states invariant I3: "Every text in `state` has passed `pii.strip`. `state` holds no display name, local part, header id or provenance" (`.doctrine/slice/004/design.md:541-542`), and pins the bounds table and "strip then cut" at `design.md:247-262`. A locked design binds its own slice; SL-005 does not silently override it — it must record that it supersedes these clauses.

No display names, local parts, other address fields"; "Texts are stripped first and cut to their bounds after, since stripping can lengthen text"; "at most 10 sender domains of at most 253 bytes"; and the strip rules "email addresses -> [email]; URLs -> scheme://host, with /[...] appended when a path or query was dropped". ### Contract stability

- Version stays **1** for additions: `README.md:119-121` ("One version number covers the whole contract, and it is 1 … new fields … consumers must ignore fields they do not know"); DEC-029's choice paragraph, same wording.
- A bump is mandatory for removal/rename/retype/meaning/ordering or a new enum value (`README.md:121-124`; DEC-029). **Risk to surface:** `SL-005 objective wording says "Additive within CLI contract v1" (`slice-005.md:54`) and IMP-006 asserts the same, but if `state.sender_domains` (`README.md:247`, `state.gleam:52-53`) disappears in favour of `from`/`sender`/`reply_to`/`to`/`cc`/`bcc`, that is a documented-field removal and DEC-029 requires a version 2 — which would break every read verb's version check for malebolge. The conservative resolution, consistent with both records: keep `sender_domains`/`sender_domains_omitted` in place and add the six lists, or accept the bump deliberately and say so.
- Reshaping `seen` later is likewise a real contract change: `IMP-006` states a changed bound fails malebolge's pinned test (update one table), while a "removed/tightened bound or a reshaped `seen`" makes malebolge withhold everything until updated.
- Nothing in README or SL-003 promises stability beyond these rules: SL-003 requires the contract be "published and tested so a change that breaks a consumer fails Screwtape's suite" (`SL-003` scope item 4), and DEC-030 puts that duty in `render_test`/CLI tests plus the README tables — no deprecation window, no schema files, no semver.
